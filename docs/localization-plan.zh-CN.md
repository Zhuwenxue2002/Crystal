# 汉化后续计划

更新日期：2026-08-03

当前主线是第六阶段“名称引用联动汉化”。阶段 1 的资源健康检查已完成；阶段 2–5 的主体工作已完成，但仍需运行验收和可复现交付。详细证据见 [当前汉化状态](localization-status.zh-CN.md)。

## 优先级 0：让汉化结果可交付

数据库的 3,823 个字段已经迁移到 `Localization/Weblate`，可以通过 Git 和 Weblate 协作。接下来应完成：

1. 将四个 PO 组件连接到 Weblate，启用建议和维护者审核。
2. 把现有术语表导入 Weblate，补充容易混淆的职业前缀和专有名词。
3. 发布匹配版本的基础数据库与 `Envir` 资源包，或建立从上游资源自动生成运行目录的流程。
4. 在干净环境执行 PO 校验、数据库回写、名称引用审计和服务端构建。

不要直接解除整个 `Build/` 的忽略规则；其中包含二进制文件、日志、备份和其他运行产物。PO 与稳定键清单应提交，活动数据库和脚本资源仍作为发布资产管理。

## 第六阶段：名称引用联动

名称不能只改数据库显示值，必须同步所有按名称查找的位置。

建议顺序：

1. NPC 名：当前检测到的有引用记录均已中文化；在 Weblate 中继续处理 141 条英文记录。
2. 物品名：按掉落表、商店、配方、任务和 GM 清单分组处理。
3. 怪物名：同步刷新配置、事件脚本、掉落表和服务端按名配置。
4. 地图与传送别名：在显示名已经中文化的基础上清理按钮和脚本引用。

普通文本和无引用名称通过 `validate-weblate`、`apply-weblate` 部署。有引用的名称会被工具阻止，维护者审核后再用带 `REFERENCE_PREFIXES` 的 TSV 同步数据库与脚本。具体命令见 [数据库与名称联动流程](localization-database.zh-CN.md)。

## 第七阶段：硬编码英文

扫描 `.cs` 中的字符串字面量并分类：

- 用户可见文本：迁移到语言 JSON。
- 日志和调试文本：仅在影响运维时汉化。
- 协议、枚举、命令、文件名和内部标识：保留英文。

新增语言键时，同时更新 `Shared/Language.cs`、英文 JSON 和中文 JSON，并校验占位符。

## 第八阶段：运行验收

完成以下路径的真实客户端验收，并记录英文残留、乱码和布局溢出：

1. 注册、登录、创建角色。
2. 打开人物、背包、技能、任务、邮件、交易、拍卖和行会界面。
3. 与 NPC 对话、接交任务、传送、购买、修理和仓库存取。
4. 击杀怪物、拾取物品、学习和使用技能。
5. 检查服务端管理端常用窗口及错误提示。

## 完成标准

- 中英文语言键完全一致，占位符零错位。
- 玩家主路径不再出现未说明的英文或乱码。
- 名称映射在数据库和全部文本引用中一致。
- 客户端、服务端可构建，服务端启动无新增加载错误。
- 干净环境能够按文档恢复与本机一致的汉化资源。
